## 1. 系统架构

| 文件 | 职责 |
|---|---|
| `BMI088Middleware.cpp` | 片选、SPI 全双工突发收发（`BMI088_transmit_receive`）、延时 |
| `BMI088driver.cpp` | 寄存器读写、初始化自检、加速度/陀螺突发读取（`BMI088_read_imu`）、温度读取（`BMI088_read_temperature`） |
| `QuaternionEKF.cpp` | 六维状态四元数 EKF（姿态角 + 陀螺零偏估计 + 卡方检验） |
| `imu_temp_ctrl.cpp` | DRDY 同步采样、恒温 PID、零漂/刻度/杆臂补偿、姿态解算与发布 |

数据流：

```
BMI088 --SPI2(hspi2, 6.25MHz)--> BMI088driver --2 次突发/帧--> imu_temp_ctrl
                                                     |-- 100Hz --> 温度 PID --> TIM3_CH4 加热 PWM
                                                     |-- 温度 1 次突发 --> 温度 PID
                                                     |-- DRDY --> EXTI --> imu_task
                                                     |             |-- 时间账本(不丢时间)
                                                     |             |-- 零漂/刻度 --> 杆臂补偿 --> QuaternionEKF --> imu_frame
```

- 通信：SPI2，`CLKPolarity = HIGH` / `CLKPhase = 2EDGE`，预分频 32，软件 NSS。
- 采样：BMI088 陀螺仪 DRDY（INT3，低有效）触发 PE12 的 EXTI15_10；
  ISR 只记录 DWT 时间间隔并通知 `imu_task`，SPI 读取和 EKF 均在任务上下文执行。
- EKF：使用**时间账本**给出的积分步长（见 §5.1.1）；通知合并的帧数只用于累计时间，
  不再被折成一个总间隔后截断。
- 超时：连续 3 次、每次 10ms 未收到 GYRO_INT 时进入 `Imu_Status_Init_Fail`，
  关闭加热并由任务周期性重试 BMI088。
- 加热：TIM3_CH4，ARR = 10000，20kHz；IMU 初始化时为该 `pwm_class` 实例显式配置
  `15%` 最大占空比，最终 CCR 写入仍在 PWM 底层执行限制。

## 2. 数据类型定义

```cpp
typedef enum
{
    Imu_Status_Uninit = 0,  // 未初始化
    Imu_Status_Init_Fail,   // BMI088 初始化失败, 任务内周期重试
    Imu_Status_Wait_Temp,   // 等待加热到目标温度（仅自标定模式）
    Imu_Status_Calibrating, // 陀螺零漂标定中
    Imu_Status_Running,     // 正常解算
} imu_status_e;

typedef struct
{
    float gyro[3];              // 已扣零漂角速度, rad/s
    float accel[3];             // 加速度, m/s^2; 解算状态下已做偏心补偿(折算到旋转中心)
    float temperature;          // 芯片温度, ℃
    euler_angle_t euler_angle;  // 欧拉角, rad
    float yaw_total;            // yaw 连续多圈角, rad
    float dt;                   // 本拍姿态积分步长, s（累计排空后的实际积分时间）
    float ref_temperature;      // 目标温度, ℃
    float heater_out;           // 加热输出, 与 TIM3 ARR 同量纲
    uint8_t status;             // imu_status_e
    uint8_t data_valid;         // 1 = 本周期数据有效
    uint32_t sample_count;      // 采样帧计数（温控分频基准）
} imu_data_resolve_t;
```

单位约定：角度 `rad`、角速度 `rad/s`、加速度 `m/s^2`、温度 `℃`。
坐标系：机体 X=前、Y=左、Z=上（右手系），yaw 绕 Z 逆时针为正，角度自 +X 起算；yaw ∈ (-π, π]。

## 3. 接口说明

| 接口 | 说明 |
|---|---|
| `void imu_task(void *argument)` | 任务入口；名称必须与 CubeMX Entry Function 完全一致（区分大小写） |
| `float imu_get_roll_rad(void)` / `imu_get_pitch_rad()` / `imu_get_yaw_rad()` | 欧拉角，rad |
| `float imu_get_yaw_total_rad(void)` | 连续多圈 yaw，rad（小陀螺/大 yaw 用） |
| `uint8_t imu_is_ready(void)` | 1 = 传感器在线且已进入解算状态 |
| `extern volatile imu_data_resolve_t imu_frame` | 解算结果结构体（含姿态、角速度、温度、加热输出） |

`imu_frame` 由 IMU 任务写、其余任务读：单个 32 位 float 字段读写原子；多字段严格一致时请自行关中断拷贝。

## 4. 初始化流程

1. `heater_pwm` 绑定 `htim3 / TIM_CHANNEL_4` 并启动，占空比立即置 0（上电安全态）。
2. `IMU_QuaternionEKF_Init(10, 0.001, 1e7, 1.0, 0.001, 0.001)`；
   后续每帧将 `QEKF_INS.dt` 更新为受限的 DRDY 实测周期。
3. 温度 PID 参数装载（`pid_set_config_pos`），`ref_temperature = IMU_TEMP_REF_C = 50 ℃`。
4. `BMI088_init()`：加速度计/陀螺仪各做「读 chip id → 软复位 → 读 chip id → 写配置并回读校验」，单次尝试 3 遍、间隔 20ms；失败则 `Imu_Status_Init_Fail`，任务内每 500ms 重试（旧版是 `while (BMI088_init());` 死等，传感器缺失会永久阻塞）。
5. 成功后按配置进入 `Imu_Status_Wait_Temp`（自标定）或 `Imu_Status_Running`；
   `imu_task` 由 CubeMX 配置的 FreeRTOS 线程入口调用。

## 5. 采样与解算逻辑

### 5.1 DRDY 同步与一帧数据读取

BMI088 陀螺仪配置为 1kHz DRDY、INT3 低电平有效。STM32 端必须在 CubeMX
中将 `GYRO_INT` 配置为下降沿 EXTI，并启用对应的 `EXTI15_10_IRQn`。
CubeMX 重新生成 `gpio.c` 和 `stm32h7xx_it.c` 后，HAL 会回调
`HAL_GPIO_EXTI_Callback`；本模块只处理 `GYRO_INT_Pin`，不在 ISR 中执行 SPI、
阻塞延时或浮点姿态计算。

任务等待 DRDY 线程标志；收到事件后读取最新一帧。**每回到循环都量一次 DWT 间隔**，
所以不管是一帧、合并多帧，还是 DRDY 超时/假唤醒，真实经过的时间都会被如实记账。

DRDY 超时（10 ms）不代表传感器停了：传感器仍在自由采样，只是中断丢了。因此超时也照常
读一次 SPI —— 读成功则正常积分并把这 10 ms 消化掉，读失败才记账等下一个有效帧。
连继 3 次超时仍会进 `Imu_Status_Init_Fail`，由任务周期重试。

#### 5.1.1 时间账本：为什么 yaw 必须一帧都不丢

**yaw 在 EKF 里没有任何绝对观测**（`GyroBias[2]` 强制 0、`xhatUpdate` 里 `temp_vector.pData[3] = 0`），
唯一信息源就是 z 轴角速度积分，而 $\theta = \int\omega\,dt$。所以
**丢时间 = 丢转角，且永远补不回来**——这不是"精度略降"，而是纯误差。

旧实现有三处会丢时间，都只在高速旋转时才显形：

| 位置 | 旧行为 | 6 rad/s 下的后果 |
|---|---|---|
| `imu_limit_dt()` 的 3 ms 上限 | 合并 5 帧（5 ms）被截成 3 ms | 每次合并丢 0.69° |
| `BMI088_read_imu()` 失败直接 `return` | 该帧时间永久消失 | 每帧丢 0.34° |
| DRDY 超时直接 `continue` | 10 ms 整段消失 | 每次丢 3.4° |

新实现把"已到达但尚未积分"的时间攒在一个计数器里（`imu_time_base_t`），每拍取一个
≤ `IMU_TIME_BASE_STEP_MAX_S`（9 ms）的步长去积分，**余额留到后续几拍排空**：

| 量 | 值 | 依据 |
|---|---|---|
| `STEP_MAX` | 9 ms | 必须 < EKF 内部 0.01 s 的 dt 复位阈值；6 rad/s 下单步只转 0.054 rad，一阶截断误差 ≈ 0.0015° |
| `STEP_MIN` | 0.5 ms | 仅作为**单帧 DRDY 周期**的合理性下限（`IMU_DT_MIN_S`），不用于抬升积分步长 |
| `PENDING_MAX` | 20 ms | 覆盖"任务被抢占十几拍"；传感器真掉线时继续攒时间只会拿陈旧样本积分，20 ms 已是 6 rad/s 下 6.9° 的上界 |

三条硬约束（改这个模块前必须遵守）：

1. **账本为空时 `take()` 返回 0，调用方跳过本拍解算**。绝不能用"最小步长"兜底——
   那等于凭空造时间（0.5 ms @ 6 rad/s = 0.17°），与丢时间一样是纯误差源。
2. **读失败/超时也要记账**（`imu_time_base_accumulate()`），由下一个有效帧补上。
3. **姿态一旦复位（`IMU_QuaternionEKF_Reset`）必须 `imu_time_base_reset()`**：
   姿态已归零，再把旧时间补进去只会积出一段凭空的角度。

投入账本的时间由 **DWT 直接量取**（`imu_measure_elapsed_dt()`），不用"帧数 × 名义周期"换算：
后者在 DRDY 抖动、通知延迟、中断丢失时都会偏，而且超时路径上根本拿不到帧数。
CYCCNT 为 32 位，550 MHz 下 7.8 s 才溢出一次，远超 `PENDING_MAX`。

**已量化的一项固有误差（采样-保持）**：合并帧时只有 1 个样本，却要代表整段积压时间，
相当于用**右端点**做矩形积分。误差 ∝ 单步步长，且**只在角速度变化时存在**（匀速旋转时为零）。
实测（20 rad/s² 加速 0.3 s 到 6 rad/s，再匀速 5 s）：

| 工况 | 转角误差 |
|---|---|
| 每拍 1 帧（步长 1 ms） | **+0.172°** |
| 每 20 拍合并 5 帧 | **+0.344°** |

即一次"起转"引入的误差 < 0.4°，远小于刻度因子误差（1% ⇒ 34°），因此**不额外引入梯形积分**：
那需要缓存上一拍样本、增加分支，收益不抵复杂度。测试 `T20` 守住这个上界。

守恒性由 `agent_analyse/tests/imu_yaw_timebase_test.cpp` 回归（测试直接从本文件抽取
`IMU_TIME_BASE` / `IMU_DT_LIMIT` / `IMU_GYRO_GLITCH` / `IMU_GYRO_CALIB` / `IMU_HEATER_POLICY`
五个标记块的源码编译，不是另写一份逻辑；抽取脚本为 `agent_analyse/tools/extract_imu_timebase.ps1`）。

`imu_limit_dt()` 只承担**单帧周期**的合理性限幅（`0.5 ms ~ 9 ms`，0/负值/NaN 回落默认 1 ms），
供野值变化率判据与"本拍未解算"时的 `dt` 发布使用；**它不参与积分时间的裁剪**。
调参时须保证 `STEP_MAX` 与 `DT_MAX` 严格低于 `QuaternionEKF` 的 `dt > 0.01` 复位阈值，
否则会每帧复位、姿态恒 0。

| 段 | 寄存器 | 长度 | 说明 | 采样率 |
|---|---|---|---|---|
| 加速度 | 0x12 ~ 0x17 | 6B | ±3g，0.0008974358974 (m/s²)/LSB | 每帧 |
| 陀螺仪 | 0x00 ~ 0x07 | 8B | 首字节为 chip id（0x0F）自检，±2000dps | 每帧 |
| 温度 | 0x22 ~ 0x23 | 2B | 11bit 有符号，0.125℃/LSB，+23℃ 偏置 | 每 10 帧 |

三处均用**单次片选内突发传输**（加速度计读时序为「地址 + 1 个哑字节 + 数据」，陀螺仪为「地址 + 数据」）。

驱动把这段拆成三个接口：

| 接口 | SPI 事务数 | 用途 |
|---|---|---|
| `BMI088_read_imu(gyro, accel)` | 2 | 1kHz 姿态主路径 |
| `BMI088_read_temperature(&t)` | 1 | 温控节拍（100Hz） |
| `BMI088_read_status(gyro, accel, &t)` | 3 | 兼容旧用法 / 调试 |

**旧实现每帧 3 次事务（温度也按 1kHz 读）**。温度的热时间常数是秒级，1kHz 采样纯属浪费带宽：
降到 100Hz 后，每帧 SPI 事务从 3 次降到 2 次，一帧读取耗时从约 43 µs 降到约 30 µs。

`BMI088_read_imu` 先在局部缓冲区解析完两段，全部成功后才一次性写回调用者缓冲区，
避免「加速度已更新、陀螺仪没更新」的半帧数据进入 EKF。

读失败（SPI 超时 / 陀螺 chip id 不符）时返回非 0，本拍不参与解算，`data_valid = 0`，
同时 **`imu_heater_output_off()`（瞬时关断，保留温控积分器）**；时间照常记账，
由下一个有效帧补上（见 §5.1.1）。

> **上层读取注意**：`imu_frame.gyro[]` / `euler_angle` 在 `data_valid == 0` 时仍保留上一拍的值
> （不做清零，避免消费者拿到 0 角速度造成误判）。消费者**必须先判 `imu_is_ready()` 或
> `data_valid`** 再使用；`chassis.cpp` 的 `chassis_eskf_update_measure()` 目前把
> `wheel_valid` / `attitude_valid` 恒置 1 且不检查 `data_valid`，属于待修项。
错误码区分 `BMI088_COM_ERROR`（总线）与 `BMI088_NO_SENSOR`（chip id 不符），便于定位是时序还是走线问题。

SPI 时钟：CubeMX 里 SPI2 为 PLL2P(100MHz)/32 = 3.125 MHz；`BMI088_com_init()` 在运行时改成
`/16 = 6.25 MHz`（BMI088 上限 10 MHz）。若个别批次在 6.25 MHz 下出现 chip id 校验失败，
把 `BMI088_SPI_PRESCALER` 改回 `SPI_BAUDRATEPRESCALER_32` 即可，不需要动 `.ioc`。

### 5.2 零漂与刻度

```
最终角速度 = (原始角速度 - gyro_bias[]) × gyro_scale[] - yaw_bias_trim
```

- `gyro_scale[]`：**刻度因子（标度因数）修正**，无量纲，默认全 1.0。
  BMI088 灵敏度存在器件容差（±1% 量级），而 z 轴误差 ∝ **总转角**且**正反转反号**——
  6 rad/s 转 10 s 时 1% 就是 34°，是"底盘高速旋转后 yaw 大量漂移"的主因之一。
  标定流程见 §5.2.3。**先扣零偏、再乘刻度**（两者都是原始域量，顺序反了会残留
  `(scale−1)·bias` 的系统偏差，详见 §5.2.3）。
- `gyro_bias[]`：默认值来自恒温静止实测；`IMU_GYRO_AUTO_CALIB_ENABLE = 1` 时改为「温度稳定 `IMU_TEMP_STABLE_S = 3 s` 后，采集 `IMU_GYRO_CALIB_S = 1 s` 的有效样本（丢弃 \|ω\| > 0.15 rad/s 的帧）求**时间加权**均值」。
  **注意**：当前默认补偿值是在 40 ℃ 下测的，而 `IMU_TEMP_REF_C` 已改为 50 ℃，
  恒温点变了 ⇒ 零偏也会变。若换上实测仍有 0.002 rad/s 量级的残余漂移，
  应把 `IMU_GYRO_AUTO_CALIB_ENABLE` 置 1，让它在实际恒温点上自标定。
  - **x/y 由 EKF 在线估计并叠加修正**（总修正量 ≈ `gyro_bias[i] + QEKF_INS.GyroBias[i]`），
    z 轴 EKF 不强估计（`GyroBias[2]` 恒为 0），因此 z 轴精度完全取决于这里的初值 + 运行期静止残差定标。
  - **旧版 z 轴初值 0.0000852 rad/s 比实测 0.0033 rad/s 小 38 倍**，是"上电后 yaw 以 0.19°/s 漂移数分钟"的根因；已按实测更正。
- `yaw_bias_trim`：运行中判定静止后修正 z 轴残差，限幅 `±IMU_YAW_TRIM_LIMIT = ±0.02 rad/s`
  （BMI088 零偏 spec 可达 ±1°/s，旧值 ±0.01 只剩 3 倍余量）。
  分两阶段：
  1. **首次静止确认后直接定标**：再以时间加权平均 `IMU_TRIM_SEED_S = 0.5 s` 求残差均值一次写入，而不是从 0 慢积分。
     旧版仅靠 20 s 时间常数积分，实测需 2~5 分钟才收敛，期间 yaw 以最高 0.19°/s 累积。
  2. 定标完成后改用 `IMU_STILL_TRIM_RATE`（1/s）慢积分跟踪温漂：`Δtrim = rate × gz × dt`，
     时间常数 ~20 s。**增益按 `dt` 归一**，否则通知合并时收敛速度会变慢数倍。
  **两个阶段都叠加同一层逐帧门控**：单帧角速度模长 `|ω| > IMU_TRIM_SEED_RATE_MAX (0.15 rad/s)` 时
  本帧不计入零偏。原因见 §5.2.1——静止判定用的是低通值，
  它比真实运动滞后 3~4 拍，机动起始的那几帧会被误判为静止。
  **静止判定的两路输入都必须低通**，否则噪声/瞬态会持续打断确认过程：
  | 判据 | 处理 | 阈值 |
  |---|---|---|
  | 角速度模长 | 0.2 s 一阶低通 | < 0.020 rad/s（≈1.15°/s） |
  | 加速度模长 | 0.2 s 一阶低通 | \|‖a‖ − 9.80665\| < 0.5 m/s² |

  - 角速度若用瞬时值：本机实测瞬时 `|ω|` 噪声峰值可达 0.020 rad/s，噪声会持续把 `still_confirm_s` 清零，
    修正永不触发（实测 `still_confirm_s` 恒为 0~2ms、`yaw_bias_trim` 恒为 0，yaw 漂移 0.19°/s）。
  - 加速度若用瞬时值：瞬时模长会偶发跳到 9.25 m/s²（约 0.55 m/s² 偏差，实测每几秒一次），
    同样打断确认（这是实机验证时定位到的第二个根因）。
    低通后单帧跳变被压缩到 1/200，而「被抬起/搬运」这类持续加速度仍会在 0.2 s 内被识别。
  - 两路都低通后，静止确认被打断的次数由 5 次/25 s 降到 0~1 次/30 s，
    静止 yaw 漂移从 0.0095 °/s 回到 **0.0001~0.0018 °/s**。
- **旧版 `CHEAT`（|ωz| < 0.003 rad/s 直接置 0）已移除**：该非线性会吃掉正常的低速转动（0.003 rad/s ≈ 0.17°/s），造成云台低速爬行/丢帧式跟踪；零漂问题改由上面的标定 + 静止残差修正解决。

### 5.2.1 陀螺野值抑制（yaw 跳变的根因防线）

**问题**：单帧 SPI 位错 / DRDY 竞争会给出几百~上千 °/s 的假角速度。EKF 对 z 轴没有任何绝对观测
（`GyroBias[2]` 强制 0、`xhatUpdate` 里 `temp_vector.pData[3] = 0`），所以**一次野值就把 yaw 永久推偏且永不恢复**。
实测捕捉到一次：板子完全静止、`accel` 模长 9.71 m/s²、chip id 校验全程通过，
静止判定用的低通角速度却在单帧从 0.0047 跳到 0.1269，随后严格按 0.2 s 一阶指数衰减
（比值 0.577 / 0.639 / 0.588 ≈ e^(−0.5)）——反推注入量 ≈ 24.8 rad/s（1420 °/s，满量程的 71%），
yaw 当场跳变 **−2.15°** 并永久保留。

**实现**（`imu_gyro_glitch_filter()`，在 `INS_Task` 里于任何积分之前调用，就地修正 `gyro[]`）：

| 判据 | 阈值 | 行为 |
|---|---|---|
| 逐轴超量程 | \|ω\| > 36 rad/s（±2000 dps = 34.9） | **永不放行**（连继多帧也一样），保持上一拍；无上一拍时置 0 |
| 逐轴变化率 | \|ω(k) − ω(k−1)\| > 10000 rad/s² × **单帧周期**（1 ms 时 = 10 rad/s） | 先保持上一拍；下一帧仍偏离则认定为真实机动并放行 |
| 距上拍间隔 | > 4 × 单帧周期 | 上一拍样本已过期，**停止变化率判据**，直接采用新样本（量程判据仍生效） |

> **必须用单帧周期，不能用本拍的积分步长**（v1.0 修正）：判据比较的是相邻两个 1 kHz
> 采样点；若用时间账本给的积分步长（合并帧时可达 9 ms），变化率阈值会被放宽 9 倍，
> 而且**合并帧越频繁越容易漏拦野值**——恰好是高转速下最容易出问题的工况。

> **长间隔必须放弃变化率判据**（v1.1 新增）：时间账本会把停颜期间的时间补进积分，
> 如果仍拿停颜前的旧值当参考，反而会把"停颜期间真实发生的反转"当成野值，
> 然后拿陈旧值去积分整段间隔。实测场景（+6 → −6 rad/s，隔 6 ms）：
> 启用长间隔判据积分 **−0.036 rad**，旧语义积分 **+0.036 rad**，**差 4.13° 且方向相反**。

该逻辑写成无副作用的纯状态机（`imu_gyro_glitch_t` + `imu_gyro_glitch_reset/filter`），
因此能被主机侧测试从本文件原样抽取编译。

- 孤立野值：下一帧即回到正常值，被**完全剔除**（验证：污染由 1.4° 降到 0.0009°）。
- 真实阶跃：进、出各滞后 1 帧，两者误差**互相抵消**（验证：净积分误差 0）。
- 噪声底：高斯噪声 sd = 0.004 rad/s 连续 20000 帧，**零误判**。
- 该函数只做数值修正，不保留任何统计量，因此不占用额外 RAM、不参与解算。

### 5.2.2 yaw 零漂的传递路径（为什么要单独给 trim 加门控）

EKF 对 z 轴没有任何绝对观测（`GyroBias[2]` 强制 0、融合时 `temp_vector[3] = 0`），
所以 **yaw 的唯一信息源就是 z 轴角速度的积分**。整条链路只有三个会引入固定偏置的地方：

```
原始陀螺 z 轴 --(− gyro_bias[2])--(× gyro_scale[2])--(− yaw_bias_trim)--> gz --> EKF 四元数 --> Yaw
                        ↑ 静态标定(零偏)      ↑ 静态标定(刻度)     ↑ 静止残差积分
```

三者中前两个是**原始域**标定量，顺序固定：**先扣零偏（加法，rad/s）、再乘刻度（乘法，无量纲）**。
反过来做会残留 `(scale−1)·bias`：scale=1.012、bias=0.003 rad/s 时残留 3.6e-5 rad/s
（0.002 °/s），转速越高越不显眼，但静置时会白白让 yaw 慢慢爬。

实测验证（静止台，40 ℃）：

| 量 | 60 s 内变化 | 折算速率 |
|---|---|---|
| `QEKF_INS.YawTotalAngle`（EKF 输出，度） | +0.0333 ° | **+9.7e-6 rad/s** |
| 1 kHz 陀螺积分 ∫gz·dt | +5.93e-4 rad | **+9.9e-6 rad/s** |

两者相差 2 %，说明 **EKF 没有额外引入漂移，yaw 漂移 100 % 来自 z 轴残余零偏**。
这条结论是后续所有调参的前提：不要在 EKF 侧找零漂，要盯 `gyro_bias[2]` 与 `yaw_bias_trim`。

`yaw_bias_trim` 的积分器是一个时间常数 20 s 的一阶低通，它的噪声底可算出来：
逐帧噪声 σ ≈ 4e-3 rad/s、增益 5e-5、1 kHz，稳态抖动 ≈ σ·√(1/(2·T·fs)) ≈ **2e-5 rad/s**。
也就是说**任何小于 2e-5 rad/s（0.0011 °/s）的零偏，在这个结构下都调不掉**，加大增益只会同步放大噪声。
实测稳态就在这个量级（见 §7 实测表），继续调增益收益很小；
若要再降一个数量级，需要偏置-温度模型（降温/升温各测一条曲线），不是改增益能解决的。

**机动会把 trim 污染掉（v0.8 修复）**：静止判定读的是 0.2 s 低通角速度，比真实运动滞后 3~4 拍。
归档数据里能直接看到这类帧被计入 trim：

| 时刻 | 该拍 z 轴角速度 | 静止判定用低通值 | Δ`yaw_bias_trim` |
|---|---|---|---|
| 120.22 s | −0.163 rad/s | 0.0165（仍判静止） | **−1.9e-4 rad/s** |
| 140.34 s | −0.315 rad/s | 0.1437（仍判静止） | **−2.1e-4 rad/s** |

单次机动就能留下 2e-4 rad/s ≈ **0.0115 °/s** 的固定偏置，要 20 s 才衰减掉。
v0.8 起 trim 的积分再叠加一层瞬时角速度门控（§5.2），这几帧直接被丢弃。

### 5.2.3 高速旋转下 yaw 大量漂移：刻度因子与丢时间

**现象**：底盘在水平面以 3.5 ~ 6 rad/s 旋转一段时间后，yaw 累积出几十度偏差，且不随静止而回正。

**根因分三类，必须分开定案**（都在 z 轴积分链上，因为 yaw 无绝对观测）：

| 机制 | 误差 ∝ | 正反转是否反号 | 6 rad/s × 10 s 下的量级 |
|---|---|---|---|
| 零偏残余 $b_z$ | **时间** | 否（始终同向） | 0.003 rad/s → 1.7° |
| 刻度因子 $s\neq1$ | **总转角** | **是** | 1% → 34° |
| 丢时间（少积分） | **漏掉的时长** | 否（总是少算） | 漏 10% → 344° |

所以\"高速才出问题\"几乎必然是后两项：零偏项与转速无关，低速旋转同样会漂。

**定案实验（10 分钟）**

- **实验 A（刻度 vs 丢时间）**：静止记录 yaw → 正向匀速转 10 圈回零位 → 记录 → 反向转 10 圈回零位 → 记录。
  - 两次误差**反号** ⇒ 刻度因子，$s = \dfrac{2\theta_{true}}{\lvert\Delta_{正}\rvert+\lvert\Delta_{反}\rvert}$；
  - 两次误差**同号** ⇒ 丢时间（先查 §5.1.1）。
- **实验 B（零偏 vs 其余）**：同一位置用 1 / 2 / 4 / 6 rad/s 各转**固定圈数**。
  - 误差随**圈数**线性、与用时无关 ⇒ 刻度因子；
  - 误差随**用时**线性、与圈数无关 ⇒ 零偏。

**落地**：`gyro_scale[3]`（无量纲，默认 1.0）与 `gyro_bias[3]` 一起交给
`imu_gyro_calibrate()`，在 `INS_Task()` 的 `Imu_Status_Running` 分支里一次算完：

```cpp
gyro[i] = (gyro[i] - gyro_bias[i]) * gyro_scale[i];   // 两者均为原始域标定量
```

两个约束：

1. **必须在 `Running` 分支内做**，不能提到 `switch` 之前：`IMU_GYRO_AUTO_CALIB_ENABLE`
   的零偏标定需要的是**原始域**样本。
2. **必须在野值抑制之后**：`imu_gyro_glitch_filter()` 的上一拍基准存的是原始域数据。

改完 `gyro_scale` 后必须**重新标 `gyro_bias[]`**（刻度变了，同一批原始数据的均值也跟着变）。

**当前标定值（2026-11-03 实车，两轮独立测量）**：

| 轮次 | 条件 | 段数 | 圈数 | 残差 SD | 解出零偏 | k | 建议 scale |
|---|---|---|---|---|---|---|---|
| ① | scale=1.0000 | 3 | 2/6/9（不等） | 5.14° | **0.287 °/s**（可疑）| 1.00891 | 0.9912 |
| ② | scale=0.9923 | 6 | 5/5/5/4/5/5 | **1.10°** | **0.011 °/s**（可忽略）| **1.00646** | **0.99356** |

**采用轮次 ② → `gyro_scale[2] = 0.9936`**。

理由：② 的自由度 4（① 只有 1）、残差标准差小 4.7 倍、圈数一致、且解出的零偏接近零
（说明恒温到位、`gyro_bias[]` 已对）。① 解出 0.287 °/s 的"零偏"在物理上不合理
（静止时肉眼可见），说明那一轮数据被温度漂移或未稳的零偏污染，其 k 也随之失真。

> ⚠ **两轮 k 相差 0.24%**，超出各自的批内精度，属 MEMS 刻度温漂量级。
> 因此换板、或改动 `IMU_TEMP_REF_C`（恒温点）后都必须重新标定。

**关键排除项**：固件 `yaw_total` 变化（−82.1707 rad）与用 **CSV 时间戳**做的
`∫gz·dt` 梯形积分（−82.3026 rad）只差 **0.16%**。若 0.8% 来自 dt 偏大，两者会差 0.8%；
实际只差 0.16% ⇒ **时间基准是对的，误差纯粹出自陀螺读数**。这是区分「刻度误差」与
「时间/X 尺度误差」的判据，比只看 yaw 本身可靠。

> **注意观察方式**：`euler_angle.yaw` 是折叠到 $(-\pi,\pi]$ 的**锯齿**，它的"最大值"
> 永远 $≤\pi$，且受采样率影响——高速旋转时采样点可能错过峰顶（实测同一次转动里
> 峰值会在 2.63~2.96 rad 之间跳）。**要看转了多少角度，必须看 `yaw_total`**
> （连续多圈，旋转时单调）。历史曲线工具请把 y 轴范围设到 `[-3.2, 3.2]`，
> 否则锯齿的负半周会被自动缩放裁掉，看起来像"只转到 2.9 rad"。

**为什么不在 EKF 里估**：`GyroBias[2]` 被强制 0，且 `xhatUpdate` 里 `temp_vector.pData[3] = 0`，
z 轴既无绝对观测也无速度观测，EKF 无法把刻度误差与真实转动区分开。这是结构性的，
只能靠外部标定。

### 5.2.4 刻度因子标定与验证（操作手册）

#### 一、数学基础

设传感器增益误差 $k$（$\omega_{读数}=k\,\omega_{真}$），固件用 `scale = s` 换算，则积分角

$$\Delta = k\,s\,\theta_{真} + b\,T$$

$b$ 为残余零偏。有 **两个未知数**（$k\,s$ 与 $b$），必须用两种办法之一解耦：

| 办法 | 条件 | 公式 | 可靠性 |
|---|---|---|---|
| **整圈取整** | 真转整圈 $N$ | $N=\mathrm{round}(\lvert\Delta\rvert/2\pi)$，$k\,s=\Delta/(2\pi N)$ | 中（依赖 $N$ 取整正确，要求刻度误差 < 5%）|
| **正反转配对** | 正反转**圈数相同** | $k\,s=\dfrac{\lvert\Delta_{+}\rvert+\lvert\Delta_{-}\rvert}{4\pi N}$ | 中高（零偏项相加即消，但残留 $b\,(T_+-T_-)$，时长不对称 20% 就带 0.03% 偏差）|
| **二维最小二乘**（脚本采用）| 多段，圈数/时长可不等 | 解 $\Delta_i = A\,N_i + b\,T_i$，$k\,s=A/2\pi$ | **最高**（用全部段，$b$ 是显式未知数，还能反查零偏标定质量）|

求得 $k\,s$ 后：$\boxed{s_{新} = s_{旧}/(k\,s)}$

#### 二、实验步骤（约 10 分钟）

1. **等恒温**：上电后等温度到 `IMU_TEMP_REF_C`（50 ℃）并稳定 **≥ 60 s**。
   实测两轮数据因恒温程度不同，解出的 k 相差 0.24%——温度没稳住，标定就白做。
2. **加 Live Watch**：把 `imu_frame.yaw_total`、`imu_frame.gyro[2]` 加入
   EmberProbe Live Watch（**不要用 `euler_angle.yaw`**，它是折叠锯齿，见 §5.2.3 注）。
3. **做对称实验**（推荐 5 圈 / 侧，重复 3 组）：
   ```
   静止 >= 3s → 正转整 5 圈 → 静止 >= 3s → 反转整 5 圈 → 静止 >= 3s
             → 正转整 5 圈 → 静止 >= 3s → 反转整 5 圈 → 静止 >= 3s
             → 正转整 5 圈 → 静止 >= 3s → 反转整 5 圈 → 静止 >= 3s
   ```
   - **必须真转整圈**：地面胶带标记、或车身某点对准参考物，转到同一朝向停下；
   - **每段圈数保持一致**（全 5 圈）。曾有一次中间一段转了 4 圈，导致两侧配对全部失效；
   - **正反转转速尽量相同**：时长相差 20% 会引入 0.03% 的零偏残留；
   - 转速取 **2~6 rad/s**：太慢 `gz` 小、信噪比差；太快打滑。
4. 导出 CSV。

#### 三、算 scale

```powershell
pwsh -File agent_analyse/tools/calibrate_gyro_scale.ps1 `
     -Csv <导出的.csv> -ScaleUsed <采集这份数据时代码里的 gyro_scale[2]>
```

> `-ScaleUsed` 必须填**采集这份数据时**的值，填错则推出的 k 与建议值全错。
> 这是最容易犯的错：改完代码忘了重新采集，或拿新代码去分析旧数据。

输出示例（2026-11-03 轮次 ②，6 段 29 圈）：

```
=== 旋转段 ===
  t0[s]  dur[s]    dYaw[rad]     n_raw    n_int       k*s
  93.50   14.86     -31.3916    -4.996       -5   0.99922
 112.63   11.62      31.3643     4.992        5   0.99836
 ...

=== 二维最小二乘 (估刻度 A 与零偏 b) ===
  A  (rad/圈) = 6.275057   =>  k*s = A/2pi = 0.998706
  b  (零偏)   = -0.000199 rad/s  = -0.01140 deg/s
  残差标准差  = 0.01913 rad = 1.096 deg   (自由度 4)

  零偏 b = 0.0114 deg/s, 可忽略(说明 gyro_bias[2] 标定到位)。

=== 结果 (共 29 圈) ===
建议 gyro_scale[2] = 0.99359
残余刻度误差      = -0.129 %
判定: 数据一致性好, 建议采用上面的值
```

脚本会自动：找静止平台 → 切旋转段 → 判整圈（残差 > 0.15 圈丢弃）→
二维最小二乘解 $(A, b)$ → 逐段残差 → 零偏合格性 → 一致性判定。

**怎么读这些数**：

| 输出 | 含义 |
|---|---|
| `k*s` | 传感器增益 × 当前 scale。目标 = 1.000 |
| `b` | 解出的零偏。**若 > 0.05 °/s，说明 `gyro_bias[]` 没标好**（或温度未稳）|
| 残差标准差 | 手转圈的重复性。**< 2° 优秀，> 5° 说明实验不合格** |
| 自由度 | 段数 − 2。**≥ 3 才可靠**；只有 1~2 时 k 的置信度很低 |

#### 四、写进代码

```cpp
static float gyro_scale[3] = {1.0f, 1.0f, 0.9936f};   // 用脚本输出的值
```

#### 五、验证（必做）

改完重新编译，**重做同样的对称实验**，导出第二份 CSV：

```powershell
pwsh -File agent_analyse/tools/verify_gyro_scale.ps1 `
     -Csv <改前.csv> -Scale <改前的值> `
     -CsvAfter <改后.csv> -ScaleAfter <改后的值>
```

判据（按显著性，不只看绝对偏差）：

| 残余 / 显著性 | 含义 |
|---|---|
| < 0.1% 且 < 2 σ | ✅ 收敛，无需再改 |
| 0.1%~0.2% 且 < 2 σ | 在噪声范围内，可以不改 |
| **≥ 2 σ** | **残余显著，按 `scale × (1/k·s)` 迭代** |
| 残差标准差 > 2° | 实验不合格（圈数/温度/打滑），重做 |

> $k\,s$ 是**跨固件版本可比**的指标（$k$ 只取决于硬件），所以"改前/改后"直接对比 $k\,s$ 即可，
> 不要对比 `scale` 本身。
>
> **为什么要看 sigma 而不是绝对百分比**：批内标准差越小，同样的残余越可信。
> 实测例：残余 0.127%、批内 SD 0.052% ⇒ **2.4 σ**，说明这是真误差而非噪声，值得改；
> 若批内 SD 是 0.2%，同样的 0.127% 只有 0.6 σ，改它就是在拟合噪声。

#### 六、改完刻度必须重测零偏

刻度是乘法、零偏是加法，两者都在**原始域**（§5.2.2）。改了 `gyro_scale` 后，
同一批原始数据的均值也就变了：

1. 静置（已恒温），Ozone 观察 `imu_frame.gyro[2]` 稳态值；
2. 若 $\lvert\text{均值}\rvert > 10^{-4}$ rad/s，把它按 $\div$ `gyro_scale[2]`
   折算回原始域，累加到 `gyro_bias[2]`；
3. 或者更省事：直接开 `IMU_GYRO_AUTO_CALIB_ENABLE = 1`，让它在实际恒温点自标定
   （代码已改为时间加权，见 §5.2）；
4. **或者用标定脚本反查**：最小二乘解出的 `b` 就是残余零偏。
   实测轮次 ② 解出 `b = −0.011 °/s`，说明 `gyro_bias[]` 已经到位，不用再动。

#### 七、现场调试技巧

想快速试不同值又不想反复编译时：**用 Ozone 直接改 RAM 里的 `gyro_scale[2]`**
（它是 `static float`，符号表里能看到），转几圈看 `yaw_total` 是否走准。
确认了好值再写回代码。注意断电即失效。

#### 八、常见失败原因

| 现象 | 原因 |
|---|---|
| 脚本报"不是整圈，跳过" | 没转够整圈，或中途停了；用地面标记重做 |
| 残差标准差 > 2° | 温度未稳 / 打滑 / 转速过慢 / 手抖 |
| 解出零偏 `b` > 0.05 °/s | 温度未稳，或 `gyro_bias[]` 没标好 —— 此时 k 也不可信 |
| 自由度只有 1~2 | 整圈段太少，k 的置信度低；至少做 3 组正反转（≥ 6 段） |
| `n_raw` 与整数差 0.5 左右 | 真的只转了半圈，或 `yaw_total` 被 EKF 复位打断（查是否触发 `Init_Fail`）|
| 改后 $k\,s$ 反而更差 | `-ScaleUsed` 参数填错（应填**采集该 CSV 时**代码里的值）|
| 两轮标定 k 差 0.2% 以上 | 温度不同（MEMS 刻度温漂 0.02~0.1 %/℃）；恒温后再测 |

### 5.3 EKF

- 六维状态：四元数 (4) + 陀螺零偏 (2，z 轴零偏不可观测，固定为 0)。
- 加速度模长异常（< 1 或 > 100 m/s²）时，量测方向取上一拍姿态推算的重力方向，使新息为 0、本拍不修正，避免 1/0 产生 NaN 污染状态链。
- EKF 入口拒绝 NaN/Inf 输入和非法 `dt`；滤波后检查四元数模长及欧拉角有限性，
  异常时恢复为单位四元数并让本帧姿态不可用。
- 加速度低通由 `accLPFcoef` 控制（旧版漏赋值导致 `lpf` 形参失效，滤波退化为直通，已修复）。
- **Mahony 已不在周期内调用**：其输出在本模块无消费者，原来每拍白跑一遍姿态解算（CPU 占用约翻倍），现仅保留 EKF 一路。

### 5.4 欧拉角发布

`Get_Roll/Pitch/Yaw()` 返回**度**，发布前统一乘 `BASIC_MATH_DEG_TO_RAD` 转 rad；`QEKF_INS.YawTotalAngle`（连续多圈）同样转 rad 后发布到 `yaw_total`。

### 5.5 加速度计偏心补偿（杆臂补偿）

IMU 不在刚体旋转中心时，加速度计除重力外还会读到旋转带来的两项附加加速度：

$$\mathbf a_{meas}=\mathbf a_{ref}+\boldsymbol\alpha\times\mathbf r+\boldsymbol\omega\times(\boldsymbol\omega\times\mathbf r)$$

- $\mathbf r$：**旋转中心 → IMU** 的位置矢量，单位 **m**；
- $\boldsymbol\alpha$：角加速度（rad/s²），由已标定陀螺低通后差分得到；
- $\boldsymbol\omega$：已扣零偏/刻度的角速度（rad/s）。

#### 5.5.1 坐标系语义（最容易错的一处）

$\mathbf r$ **必须填在 BMI088 芯片自身坐标系下**（即陀螺/加速度计输出的那个坐标系），
**不是机体坐标系**。原因很朴素：**叉乘只在同一坐标系内有定义**，而 $\boldsymbol\omega$、$\mathbf a$
都是芯片系的原生输出。若 $\mathbf r$ 用机体坐标量，补偿量会被减到错误的轴上 ——
量级没错、方向错一个安装角（典型症状：`‖a‖` 的大小对了，但 `accel.x/accel.y` 分量的符号/分配全错）。

安装旋转为 $C$（芯片 → 机体）时，正确换算：$\mathbf r_{chip}=C^{\mathsf T}\mathbf r_{body}$。

本模块在**芯片坐标系内完成全部计算后再交给上层**（上层 `chassis.cpp` 才做 `imu_ax/ay/az = -accel[]`
这类轴映射）。所以若芯片安装方向与机体不同（旋转 90°/180°/镜像），先把机体坐标量到的值做逆变换再填。

#### 5.5.2 不补偿的代价（三级，量级差很多）

补偿量是 $\omega^2r$（向心）与 $\alpha r$（切向）的矢量和。它的危害分三个层次，**量级差别很大，不要混用**：

**① 几何层：相对重力方向的偏角**（若加速度被完全信任时的等效角）

| 偏心 $\lvert r\rvert$ | 转速 ω | 向心项 $\omega^2r$ | 等效偏角 $\arctan(\omega^2r/g)$ |
|---|---|---|---|
| 50 mm | 3 rad/s | 0.45 m/s² | 2.6° |
| **80 mm（本车默认）** | **6 rad/s** | **2.88 m/s²（0.29 g）** | **16.4°** |
| 100 mm | 6 rad/s | 3.60 m/s²（0.37 g） | 20.2° |
| 80 mm | 加减速 60 rad/s² | **4.80 m/s²（切向）** | **26.1°** |

**② 对 EKF 姿态的实际影响（闭环实测，R = 1e7）** —— **远小于上面的几何值**

`P` 稳态对角元 ≈ 9.1e4，而 `R = 1e7` ⇒ **卡尔曼增益 K ≈ P/(P+R) ≈ 0.009**，
加速度量测每拍只按 0.9% 修正姿态。实测（真实 `QuaternionEKF.cpp`，r=(0.08,0,0)）：

| 工况 | 未补偿 roll/pitch 最大误差 | 已补偿 | 改善 |
|---|---|---|---|
| 静止（ω≡0） | 0.000° / 0.000° | 0.000° / 0.000° | 无差异（补偿项恒 0） |
| **匀速 6 rad/s（向心项）** | **0.31° / 0.14°** | 0.007° / 0.002° | 40~80 倍 |
| **频繁加减速（切向项 4.8 m/s²）** | **8.55° / 12.78°** | 0.60° / 0.62° | **14~20 倍** |
| 带真实噪声（陀螺 0.004、加速度计 0.06） | RMS 1.44° / 0.63° | 0.02° / 0.03° | 20~70 倍 |

两个反直觉但重要的结论：

1. **切向项的危害远大于向心项**（12.8° vs 0.31°）。因为匀速时是**稳态偏置**，EKF 有时间通过陀螺零偏估计把它消化掉；
   而加减速时切向项**每周期重新注入**，注入速度超过 EKF 的恢复速度（实测 pitch 误差呈缓慢振荡：
   −17.6° → −12.7° → −1.8° → +5.2° → −3.3°，恢复时间常数 >1 s），误差就累积了。
2. **调小 R 也救不回来**（R 从 1e7 降到 10，未补偿误差仍只有 0.3~0.8°）—— 因为量测是**单位化**的，
   而 P 与 R 的比值才是决定 K 的东西。**不要试图用调 R 来代替杆臂补偿。**

**③ 对 `imu_frame.accel` 语义的影响（最直接、量级最大）**

`accel` 被下游当**平移加速度**用时（打滑检测、里程计、能量模型），杆臂误差就是纯假信号：

| 转速 | 未补偿水平分量 | 折合 | 补偿后 |
|---|---|---|---|
| 3 rad/s | 0.73 m/s² | 0.07 g | 0.0000 |
| **6 rad/s** | **2.93 m/s²** | **0.30 g** | 0.0000 |
| 8 rad/s | 5.21 m/s² | 0.53 g | 0.0000 |

这是补偿**最明确的收益点**：姿态只有亚度到十几度的改善，而 `accel` 的假信号是半 g 量级。

> **向心项不会打断静止判定**（本模块文档曾写错，已纠正）：静止时 ω 必为 0 ⇒ 向心项也必为 0。
> `StableFlag` 判据要同时满足 $\lvert\omega\rvert<0.3$ 与 $\lvert\lVert a\rVert-g\rvert<0.5$，
> 而 $\omega<0.3$ 时向心项仅 0.0072 m/s²，**与 0.5 的阈值完全不冲突**。
> 卡方检验也不会因杆臂误差触发（实测 `ErrorCount` 增长 0、`yaw_total` 无回退）。

#### 5.5.4 实现要点

| 项 | 做法 | 依据 |
|---|---|---|
| 补偿位置 | `Imu_Status_Running` 分支内，零偏/刻度换算**之后**、喂给 EKF **之前** | 角加速度必须用物理量；野值进差分会伪造巨大 α |
| 向心项角速度 | 用**瞬时** ω | $\omega^2$ 是二次量，噪声不被放大；低通只会白添相位滞后（4 ms 滞后的误差 ≈ $2\omega\alpha r\tau$，比噪声贡献大 50 倍） |
| **差分时间基** | **`frame_dt`（单帧 DRDY 周期），不是 `integrate_dt`** | 差分的语义是"相邻两个 1 kHz 采样点"。时间账本的积分步长在合并帧/排空余额时可达 9 ms 且与样本间隔无关，用它会把 α **低估 88.9%**（T11 实测：20 → 2.22） |
| 长间隔判据 | `elapsed_dt > 4 × frame_dt` 时重置差分基准，本拍只做向心项 | 与野值抑制同口径。停顿后拿陈旧基准差分会把真实阶跃算成 $\Delta\omega/1\text{ms}$（+6 rad/s 阶跃 ⇒ 6000 rad/s²） |
| 滤波链 | 陀螺 4 ms 低通 → 差分 → 8 ms 低通；α 限幅 ±200 rad/s² | 1 kHz 直接差分会把陀螺噪声放大 $1/dt$ 倍（0.004 rad/s → 4 rad/s²，×0.1 m = 0.4 m/s² 假加速度） |
| 补偿量限幅 | 逐轴 ±30 m/s²，非有限值一律归 0 | 只拦异常数据把重力方向带飞；正常工况远达不到（0.1 m × 6 rad/s = 3.6 m/s²） |
| 关闭方式 | `imu_lever_arm_m` 全 0 ⇒ 直通（2000 拍随机输入**逐位不变**，T1） | 不额外加开关，避免两套代码路径 |
| 复位时机 | 传感器重连时 `imu_accel_lever_reset()`；非法输入（dt≤0/NaN/Inf）同样复位且**不改 accel** | 离线前后角速度不连续，旧基准无意义 |

#### 5.5.5 发布语义

`imu_frame.accel[]` 的取值分三种情况，使用时需知晓：

| 状态 | `imu_frame.accel` |
|---|---|
| `Running` 且本拍有积分时间（账本非空） | **补偿后**的值（等价于"IMU 装在旋转中心"） |

#### 5.5.6 现场标定与验证

1. **量几何**：卷尺量 IMU 安装面形心到旋转中心在三个方向的投影，
   按 **旋转中心 → IMU** 填数，再按 §5.5.1 变换到芯片坐标系。
2. **静态校验**：静止时 `imu_frame.accel` 模长应 ≈ 9.80665 m/s²（ω=0 时补偿项恒 0；
   若静态就变了，说明 `dt`/输入混进了异常值）。
3. **动态校验（可判符号）**：绕轴匀速旋转（如 6 rad/s），用 Live Watch 看 `imu_frame.accel`：
   - **补偿正确**：‖a‖ 仍在 9.8 m/s² 附近；
   - **没补偿**：偏离约 $\omega^2r$；
   - **符号/轴填反**：偏离约 $2\omega^2r$（补偿把误差翻倍）—— 用"偏离量是否放大一倍"直接判号。
4. **判据**：3~6 rad/s 旋转时 $\lvert\lVert a\rVert-9.80665\rvert < 0.5$ m/s²。

一个反直觉但有用的**间接判据**：在模长域，向心项的影响被压缩成 $\dfrac{\lvert\omega^2r\rvert^2}{2g}$
（2.88 m/s² → 仅 0.43 m/s²），而切向项是 $\alpha r$ 全量线性叠加。
所以"**‖a‖ 在加减速瞬间才明显跳、匀速时基本正常**"恰恰说明偏心补偿在起作用、只是 α 链有延迟；
若"**匀速旋转时 ‖a‖ 稳定偏离**"，那就是向心项/`r` 符号的问题。

## 6. 温度控制

- 周期 100Hz（采样分频 10），位置式 PID：**`Kp=180, Ki=1.2, Kd=150`**，输出限幅 1500（= 15% 占空比），目标温度 `IMU_TEMP_REF_C = 50 ℃`。
- **积分限幅 = `IMU_TEMP_PID_INTEGRAL_LIMIT = 500`**，当前 `Ki = 1.2` ⇒ I 项单独最多
  `500 × 1.2 = 600 counts`（6% 占空比），留出 P 项 1500 的余量；同时它也是真正的抗饱和
  上限：升温阶段误差很大时，I 项不会无限累积。
  历史上曾用 `Kp=180 / Ki=5 / Kd=120 / 积分限幅=300`（即 `max_out/Ki` 的推导），
  实测 40 ℃ 目标只能稳在 39.1 ℃；后来重调为当前参数。**改任一 PID 参数时都要同步核对
  积分限幅与 `IMU_TEMP_OVERHEAT_C` 的关系**，不要只改 Kp/Ki/Kd。
- **条件积分抗饱和**：`imu_heater_keep_integral(out, out_max)` 判决 —— 输出顶到上限时撤销本拍积分（升温阶段误差很大，若继续累积，Ki 会在一两秒内把积分推到限幅值，之后必然大超调）；输出被压到 0（偏热）时同样撤销本拍积分。
  两者合起来才既能顶到 15% 满功率升温、又不超调。`imu_heater_clamp_out()` 负责把输出夹进 `[0, out_max]`。
  两条判据都抽成了纯函数，由 `T21` 回归（含 NaN 方向安全性：NaN 落入"撤销"分支，不会冻结在垃圾值上）。
- **两种关断必须分开**（v1.4）：

  | 场景 | 函数 | 输出 | 积分器 |
  |---|---|---|---|
  | 单帧 SPI 毛刺 / 数据 NaN | `imu_heater_output_off()` | 立即 0 | **保留** |
  | 传感器掉线 / 初始化失败 / 温度超范围 / 过温 | `imu_heater_safe_off()` | 立即 0 | **清零** |

  旧版一律清零，后果是**偶发 SPI 毛刺就把温控打回冷启动**。按 `Ki=1.2`、误差 0.5 ℃、
  100 Hz 估算，积分器从 0 重建到稳态（500）需要 **1000 拍 = 10 s**（`T22` 实测），
  期间加热功率显著不足、温度明显下跌。
  反过来，硬故障必须清零：否则恢复后会拿"掉线前冷的时候攒的积分"去猛加热（过温风险）。
  毛刺路径不会无限期保留积分：`read_fail_count` 达到 `IMU_READ_FAIL_LIMIT` 后进入
  `Imu_Status_Init_Fail`，下一拍就命中硬故障分支。
- **温度与姿态解耦**：温度只在温控节拍读取（100Hz）。温度读失败时立即断开加热，但本拍的陀螺/加速度仍然正常送入 EKF，
  姿态不中断。反之姿态异常也不关加热。两侧各自独立降级，避免一处故障掩盖另一处。
- **输出限幅在模块内做**：`pid_calc()` 的 `PID_POSITION` 分支本身不做输出限幅，
  必须在 `imu_temperature_ctrl_step()` 里显式夹到 `[0, IMU_TEMP_PID_OUT_MAX]`，
  否则 `imu_frame.heater_out` 观测值会远超上限（只有 PWM 底层兜底，Ozone 上看到的数是错的）。
  NaN/Inf 无法被 `basic_math_constrain` 拦住（NaN 与任何值比较都为假），所以先单独判掉。
- 安全阀：
  | 条件 | 动作 |
  |---|---|
  | 温度 < `IMU_TEMP_VALID_MIN_C`（-20 ℃）或 > `IMU_TEMP_VALID_MAX_C`（100 ℃，读数异常） | 加热置 0，清积分 |
  | 温度 > `IMU_TEMP_OVERHEAT_C`（60 ℃，过温） | 加热置 0，清积分 |
  | 连续读不到 GYRO_INT 或 SPI 数据 | 加热置 0，进入初始化失败并周期重试 |
- 上电/初始化失败期间占空比恒为 0。安全关断会记住上次下发的占空比，
  已经是 0 时跳过 CCR 写入，避免 1kHz 故障路径上每帧重复写寄存器。

实机验证（静止台上，环境 25 ℃ 左右，当时目标 40 ℃）：约 40 s 由 39.1 ℃ 升到 40 ℃，最大超调 0.125 ℃（1 LSB），
稳态在 39.75 ~ 40.25 ℃ 之间来回 1 个 LSB，收敛期占空比约 9 ~ 13%。
**当前代码目标是 50 ℃**（`IMU_TEMP_REF_C`），上表是 40 ℃ 目标的历史实测，换目标后需重新验证。

状态字段（固件只保留实现必需的项，不保留诊断统计量；需要排查时用调试器直接观察内部静态变量）：

| 字段 | 健康值 | 说明 |
|---|---|---|
| `status` | 4 (`Imu_Status_Running`) | 工作状态 |
| `data_valid` | 1 | 本帧传感器数据有效 |
| `sample_count` | 持续增长 | 采样帧计数（温控分频基准） |
| `temperature` | 39.75 ~ 40.5 ℃ | 芯片温度 |
| `heater_out` | 0 ~ 1500 | 加热输出（与 TIM3 ARR 同量纲） |
| `dt` | ≈ 0.001 s | 本拍姿态积分步长（正常等于采样周期；通知合并/断帧后可达 9 ms） |
| `gyro[3]` / `accel[3]` | — | 已扣零漂角速度 / 加速度（`accel` 在 `Running` 下为**补偿后**值，见 §5.5.5） |
| `euler_angle` / `yaw_total` | — | 欧拉角 / 连续多圈 yaw，rad |

实测（2026-10-26，静止台上，40 ℃ 恒温）：

| 指标 | 实测值 |
|---|---|
| 采样率（外部观测） | 998.7 Hz（长期稳定，抖动 < 0.1 Hz） |
| 一帧 SPI 读取耗时（外部观测） | 约 30 µs（优化前约 43 µs） |
| 上电 4.8 s 时 yaw 累积 | **−0.034°**（修复前同一时刻 −8.06°） |
| `yaw_bias_trim` 收敛 | 上电 ~1 s 内定标完成，稳态 2e-5 ~ 6e-5 rad/s |
| 静止 yaw 漂移（归档 8 min 窗口） | −0.020 °/min，累计 −0.085°，无跳变 |
| 静止 yaw 漂移（另一轮 69 s 窗口） | **−0.08 °/min（−2.3e-5 rad/s）**，与 1 kHz 陀螺积分 −0.081 °/min 一致 |
| yaw 估计短期抖动 | ±0.1 °（69 s 内 0.21 ° 峰峰值）—— 这已是估值的噪声底，比它更小的"漂移"测不出来 |
| 温控稳态 | 39.75 ~ 40.5 ℃（超调 0.125 ℃ = 1 LSB） |

> **读数注意**：`QEKF_INS.YawTotalAngle` 的单位是**度**（`imu_frame.yaw_total` 才是 rad）。
> 换算：1e-5 rad/s = 0.00057 °/s = 0.034 °/min ≈ 2 °/h。

上电首帧的 `dt` 约 0.082 s 已被定位：**不是丢中断**，而是 `BMI088_LONG_DELAY_TIME`
的陀螺软复位死区（这段时间不产生 DRDY），只在开机出现一次，且被 `IMU_DT_MAX_S`
钳到 9 ms 以内（时间账本把它当作一次正常积压排空），属良性。

姿态可用性已与传感器数据有效性**解耦**：EKF 异常时 `imu_is_ready()` 返回 0，
但 `data_valid` 仍保持 1、加热照常闭环。温控只依赖 `temperature`，与姿态无关，
把整链一起关掉会掩盖真正的温控故障。

## 7.1 EKF 内存分配约束（重要）

`Kalman_Filter_Init()` 通过 `pvPortMalloc()` 分配 25 块矩阵缓冲区（约 1.9 KB）。
FreeRTOS 堆不足时返回 `NULL` 且**不报错**，此后矩阵运算会写到地址 0，
四元数变成 NaN，姿态恒为 0 且每帧复位。

本机曾因堆不足（`configTOTAL_HEAP_SIZE = 15360` 被 7 个动态任务占掉 13824）
导致 `Q/FT/K/S/temp_*` 全部为 `NULL`。现已把所有 FreeRTOS 任务改为**静态分配**，
堆完整留给 EKF。

- `IMU_QuaternionEKF_IsReady()` 在初始化后校验全部 16 个关键指针；
- 任一为空则 `ekf_ready = 0`，`imu_attitude_step()` 直接返回，不调用 Update；
- 健康判据：姿态角持续更新且 `imu_is_ready() == 1`；若姿态恒为 0，用调试器看 `ekf_ready`。

## 8. 输出限幅汇总

| 位置 | 限幅 |
|---|---|
| 温度 PID 输出 | `[0, IMU_TEMP_PID_OUT_MAX]`（模块内显式限幅 + NaN/Inf 保护） |
| 积分项 | `±IMU_TEMP_PID_INTEGRAL_LIMIT`（= `max_out / Ki`）+ 输出饱和时冻结积分 |
| 静止残差零漂 | `±IMU_YAW_TRIM_LIMIT` |
| 陀螺积分步长 | `[0, IMU_TIME_BASE_STEP_MAX_S]`；账本累计 `≤ IMU_TIME_BASE_PENDING_MAX_S` |
| 偏心补偿量 | 逐轴 `±IMU_LEVER_CORR_MAX_M_S2`（30 m/s²）；角加速度 `±IMU_LEVER_ALPHA_MAX_RAD_S2`（200 rad/s²） |
| 偏心差分基准有效期 | 距上拍 `> IMU_LEVER_GAP_FRAMES`（4）× 单帧周期 即作废，本拍只做向心项 |
| 加热 PWM 占空比 | IMU 初始化时配置的 `pwm_class` 实例限制到 `[0, 15%]`，最终写 CCR 前再次执行 |

`pwm_class` 默认允许通用设备使用 `[0, 100%]`，每个实例/通道可以在初始化时调用
`set_max_duty_ratio()` 配置自己的最大值。限制是单调收紧的：一旦配置为 15%，
后续业务代码不能通过再次调用该接口提高上限。因此蜂鸣器、电机、舵机等其他 PWM
实例不会被 IMU 的 15% 策略影响。
对于 IMU 加热器，即使 PID 参数、调用方输入或浮点值异常，最终写入定时器的比较值也不会超过 15%。
NaN/Inf、传感器无效、过温、初始化失败、PWM 启动失败和停止路径均写入 `CCR4 = 0`。
该软件限制不能替代硬件验证：上车前仍必须确认 PB1 的电气连接、驱动器有效电平、
MOSFET 栅极保护、24V 加热回路与 H7 地之间不存在反灌电压。

## 9. CubeMX 配置与上车前检查

本模块已登记到 `CMakeLists.txt`，但不直接修改 CubeMX 生成的
`Core/Src/freertos.c`、`Core/Src/gpio.c` 或 `Core/Src/stm32h7xx_it.c`。

### 9.1 GPIO/EXTI 配置

1. 打开 `infantry.ioc`，确认 `PE12` 的标签为 `GYRO_INT`，信号选择
   `GPIO_EXTI12`，触发边沿为 **Falling Edge**；PE10 若只作 DRDY 观测，
   建议改为普通 `GPIO_Input`（加速度计 INT1 为 800Hz DRDY 推挽输出，
   配成 EXTI 会产生每秒 800 次无效中断）。
2. 上下拉按硬件原理图设置；当前 BMI088 驱动配置为推挽低有效，默认使用
   `No Pull`。
3. 在 NVIC Settings 中勾选 **EXTI line[15:10] interrupts**，优先级 `5`、子优先级 `0`
   （必须数值 ≥ `configLIBRARY_MAX_SYSCALL_INTERRUPT_PRIORITY = 5`，
   否则 ISR 中的 `osThreadFlagsSet` 会触发 FreeRTOS 断言）。
4. 点击 Generate Code。不要手动编辑生成的 `gpio.c` 或 `stm32h7xx_it.c`。

### 9.2 FreeRTOS 线程配置

1. 在 Middleware > FREERTOS > Tasks and Queues 中新增任务：
   - Task Name：`ins_task_rtos`
   - Entry Function：`imu_task`（**必须与 `imu_temp_ctrl.h` 中的声明逐字符一致，
     含大小写**；C 语言区分大小写，写错会退化成 CubeMX 生成的空壳弱函数，
     编译不报错但 IMU 完全不工作）
   - Priority：`High`(40)。当前实车配置即此项；`Realtime`(48) 会每秒 1000 次抢占
     `gimbal`/`shoot`/`safe_daemon`(24)，不建议
   - Stack Size：至少 `1024` words；若当前版本显示字节，则填写至少 `4096` bytes
   - Allocation：`Static`（**必须**。Kalman 需要约 1.9 KB 堆，动态任务会把堆吃光，
     导致 EKF 矩阵指针为 NULL、姿态恒为 0；静态分配的栈不占用 `configTOTAL_HEAP_SIZE`）
   - Code Generation Option：`As weak`（由本模块的强定义覆盖）
2. 生成代码后确认 `freertos.c` 中只有一个 `imu_task` 线程创建项，
   且其定义在链接结果中不是 `W`（weak）符号：
   ```powershell
   arm-none-eabi-nm build\Debug\infantry.elf | Select-String imu_task
   ```
   应看到 `T imu_task`，并可用 `arm-none-eabi-addr2line` 确认它落在
   `imu_temp_ctrl.cpp`。
3. 不要在其他用户代码中再次调用 `osThreadNew(imu_task, ...)`。

### 9.4 IMU 任务对其它实时外设的影响（WS2812 等）

IMU 任务优先级 `High`、周期 1 kHz，单次连续占用 CPU 实测约 **130 µs（峰值约 190 µs）**。
这个时间就是**所有低优先级任务能被一次性阻塞的上限**，对靠软件/阻塞 SPI 抖动时序的外设是硬约束。

**已踩过的坑：WS2812 偶发闪停。** WS2812 用 SPI6 位流模拟单总线时序，
一帧 25 字节 ≈ 46.5 µs；灯珠在数据线持续低电平约 50 µs 后就会锁存当前已收到的位。
而 SPI6 只能走 HAL 阻塞发送（BDMA 访问不到 DTCM 里的缓冲区），HAL 在
`FifoThreshold = 01DATA` 下每次只往 FIFO 塞 1 字节，CPU 一旦被抢占超过 1.9 µs
移位时钟就停顿——停顿超过 50 µs 就会把半帧当一帧锁存，表现为灯短暂变暗/熄灭。

- 开启 IMU 前，能打断发送的任务都慢得多、也轻得多，所以不复现；
- 开启 IMU 后，实测 **5.6% 的帧被截断**（约每 1.8 s 闪一次）；
- 修法：`ws2812_write_color()` 在发送期间 `osKernelLock()` 挂起调度器。
注意它只禁止**任务切换**，中断照常响应（本工程 IRQ 全为优先级 5，单次只有几微秒，
远小于 50 µs 门限）。

后续新增"用阻塞方式按时序翻转引脚"的外设（软件 SPI/I2C 从机、单总线 DHT11、
红外编码等）必须同样处理，不能靠"任务优先级低所以慢"来保证时序。

### 9.5 上车前检查

   - TIM3_CH4 确实接加热电阻（IMU 初始化会配置该实例 15% 上限并立即以 0% 启动）；
   - 不得通过其他代码直接写 `TIM3->CCR4` 或绕过 `pwm_class` 启动加热；
   - SPI2 的 `ACC_CS / GYRO_CS` 与 BMI088 安装方向一致；
   - 示波器确认 `GYRO_INT` 为约 1kHz 的下降沿，且没有长时间低电平/毛刺；
   - 若硬件实际输出为高有效，必须同时修改 BMI088 INT3 电平配置和 EXTI 边沿，
     不得只改其中一侧；
   - 先关加热（把 `IMU_TEMP_PID_OUT_MAX` 置 0）验证姿态解算，再逐步放开温控。

## 10. 常见错误与排查

| 现象 | 可能原因 | 处理 |
|---|---|---|
| `status` 长期停在 `Imu_Status_Init_Fail` | SPI 无响应、片选错误、供电缺失 | 用调试器看 `BMI088_init()` 返回值枚举，或断点看 `read_fail_count` |
| `data_valid` 频繁为 0 | 陀螺 chip id 校验失败（SPI 时序/时钟过高） | 把 `BMI088_SPI_PRESCALER` 改回 `SPI_BAUDRATEPRESCALER_32`，检查 CPOL/CPHA 与走线 |
| yaw 静止缓慢漂移 | `gyro_bias[2]` 与实际零偏不符，或静止修正未生效 | 用调试器看 `yaw_bias_trim`（应已非 0 且稳定，稳态 < 1e-4）与 `still_confirm_s`（应停在 0.5）；仍漂则开 `IMU_GYRO_AUTO_CALIB_ENABLE` 重新标定 |
| **机动后 yaw 出现固定偏置（回位后角度差 0.1~1°）** | 机动过渡帧被误判为静止，污染了 `yaw_bias_trim` | v0.8 已用瞬时角速度门控修复；如再现，用调试器确认门控阈值 `IMU_TRIM_SEED_RATE_MAX` 与 `yaw_bias_trim` 的阶跃时刻 |
| **yaw 突然阶跃几十度/几度后永不回正** | **陀螺单帧野值（SPI 位错/DRDY 竞争）被直接积分** | 已由 `imu_gyro_glitch_filter()` 拦截；如再现需在其 `st->prev` 处断点确认野值幅值。注意 yaw 无绝对基准，一旦被污染只能靠复位恢复 |
| 姿态在 DRDY 丢失时反而正常、高优先级任务很忙时 `dt` 变大 | 正常现象：超时路径会照常读一次传感器，时间账本按真实间隔排空 | 不用处理；但若 `imu_frame.dt` 长期停在 9 ms，说明 1 kHz 任务已接近饱和 |
| 姿态恒为 0 / 不更新 | FreeRTOS 堆不足，Kalman 矩阵指针为 NULL | 用 `IMU_QuaternionEKF_IsReady()` 确认；把任务改静态分配或增大 `configTOTAL_HEAP_SIZE` |
| yaw 低速跟踪抖动/爬行 | 曾开启 `CHEAT` 小值截断 | 本版已移除，改查机械摩擦与云台前馈 |
| 采样率明显低于 1000 | 任务被更高优先级任务长期占用、DRDY 丢中断 | 确认 IMU 任务优先级为 `High` 且 `GYRO_INT` 是唯一的 1kHz 中断源；用逻辑分析仪测 `GYRO_INT` 频率 |
| 温度长时间上不去 | 加热占空比太小 / 目标温度过高 | 先检查硬件驱动、有效电平和传感器反馈；不得仅为升温而绕过 `TIM3_CH4` 的底层 15% 上限 |
| 温度超调大 | 积分过大 | 降 `IMU_TEMP_PID_KI`；`IMU_TEMP_PID_INTEGRAL_LIMIT` 已按 `max_out / Ki` 推导，不要单独调小，否则会重新引入稳态误差 |
| **高速旋转（3.5~6 rad/s）一段时间后 yaw 累积几十度偏差** | ① 丢时间（旧 dt 3ms 截断 / 读失败丢帧）② 陀螺刻度因子误差（典型 ±1%） | 先看正反转是否反号：**反号 = 刻度**（改 `gyro_scale[2]` 后重标 `gyro_bias[2]`），**同号 = 丢时间**（查 §5.1.1 的时间账本是否在跑，`imu_frame.dt` 应稳定在 1ms） |
| `imu_frame.dt` 长时间停在 9 ms | 任务持续被抢占，或 DRDY 中断被关掉一段时间 | 看时间账本 `gyro_time_base.pending_s` 是否长期 > 0；若积压无法排空，说明 1 kHz 任务已被压到接近饱和，优先降 IMU 任务的单次耗时 |
| 野值抑制看起来"不生效" | 合并帧时阈值被放宽 | v1.0 起改用单帧周期，v1.1 起把逻辑抽成纯状态机并有专项用例（T11~T16）守住 |
| **旋转中 roll/pitch 偏 8~13°（加减速时）** | 切向项 $\alpha r$ 未补偿或 $r$ 偏大 | 查 §5.5.2②：切向项危害大于向心项；配置 `imu_lever_arm_m` 后复测 |
| **旋转中 roll/pitch 只偏 0.3~0.8°** | 向心项影响被 R=1e7 压小（K≈0.009），**属正常量级，不是没补偿的迹象** | 用 C9 的 `accel` 水平分量（0.3~0.5 g）判断补偿是否生效，比看姿态灵敏得多 |
| **匀速旋转时 ‖a‖ 稳定偏离，加减速时反而正常** | $r$ 有常值错误（方向或大小），向心项没补对 | 同上，复核 $r$ 与坐标系 |
| **加减速瞬间 ‖a‖ 跳一下（约 1 m/s²）很快回稳** | 正常：α 滤波链固有 26 ms 爬升（见 §5.5.7 T18） | 不用处理；若抖动不可接受，减 `IMU_LEVER_ALPHA_LPF_S`（代价是噪声放大） |
